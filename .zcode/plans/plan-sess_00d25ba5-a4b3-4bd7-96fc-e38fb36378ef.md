实现目标：在软件的系统配置中新增“HTTP 代理”输入项/按钮说明：出口流量将经此代理；留空时直连，不读取系统环境变量。修改后需重启应用生效。

计划：
1. 定位并修改系统配置 UI
   - 在现有“系统配置/设置”页面新增 HTTP 代理配置项。
   - 文案使用用户指定语义：`HTTP代理`，说明：`出口流量将经此代理；留空时直连，不读取系统环境变量。修改后需重启应用生效。`
   - 输入值支持常见格式，例如 `http://127.0.0.1:7890`；留空表示禁用代理。

2. 扩展配置持久化结构
   - 在现有配置模型/配置文件中新增字段，例如 `http_proxy` 或 `proxy_url`。
   - 保持向后兼容：旧配置没有该字段时默认空字符串。
   - 保存配置后不立即热切换，提示/依赖“重启应用生效”。

3. 修改网络请求初始化逻辑
   - 找到视频生成链路中调用 AI/API/下载资源的统一 HTTP 客户端或请求封装。
   - 启动时读取应用配置中的 HTTP 代理字段。
   - 如果字段为空：显式直连，并禁用读取系统环境变量。
   - 如果字段非空：所有出口 HTTP/HTTPS 请求经该代理。
   - 对 Python 常见库按实际项目实现适配：
     - `httpx`：设置 `trust_env=False`，并在有代理时传入 `proxy`/`proxies`。
     - `requests`：设置 `Session.trust_env = False`，空代理时不传 proxies，有代理时传 `{"http": proxy, "https": proxy}`。
     - OpenAI/兼容 SDK：优先通过自定义 `http_client` 传入禁用环境变量和代理后的 httpx client。
   - 避免依赖 `HTTP_PROXY`、`HTTPS_PROXY`、系统代理或环境变量。

4. 验证
   - 检查配置保存/读取不报错。
   - 运行项目已有测试或至少执行启动/导入检查。
   - 如项目没有自动测试，则做静态语法检查，确认改动文件无语法错误。

5. 交付说明
   - 总结修改文件、配置项名称、代理格式示例。
   - 说明：修改代理配置后需要重启应用才会影响后续网络请求。
